# snestack - Personal Decision-Support Harness

A "thin harness, fat skills" system for encoding how the user actually thinks about a decision — not a single-purpose tool. Deterministic code fetches data; markdown skill files hold the judgment; a domain-agnostic core harness loads a named skill, resolves the context it declares it needs, and runs it through Claude. `domains/financial/` (investment recommendations across a portfolio/watchlist, based on the user's own stated investment philosophy) was the original domain; `domains/calendar/` (read-only Google Calendar) is the second, added specifically to prove the harness generalizes beyond investing. `domains/travel/` (cataloging past trips from Gmail + Google Maps Timeline into `brain/travel/<year>/`) is the third — and the first domain the harness can't run end-to-end itself, since it has no Gmail access; see that domain's note below. More domains are expected — anywhere the pattern "fetch some data, apply my own judgment to it" shows up in the user's life is a candidate.

## Setup

```bash
cd node
npm install
cp .env.example .env
# Edit .env with your API keys — see node/README.md
```

## Architecture: thin harness, fat skills

This project follows Garry Tan's "thin harness, fat skills" model, fully migrated (see git history on `move-to-skills-based` for the six-step migration). Layout:

- `node/src/core/` — domain-agnostic harness: `skillLoader` (parses skill frontmatter), `domainRegistry` (reads `config/domains.json`, loads a domain's `contextTools`), `executor` (runs a prompt through Claude), `runSkill(domain, skill, subject)` (the actual entry point), plus `db`, `config` (including the `cheap`/`normal`/`expensive` model tiers a skill picks with `model:` in its frontmatter), `logger`, `errors`. Never references anything domain-specific.
- `node/src/config/domains.json` — registers each domain's `skillsDir` and `contextToolsModule`.
- `node/src/domains/financial/` — the investing domain: `skills/` (start at `skills/INDEX.md` — `long-term-quality.md`, `swing-trading-large-cap.md`, `private-company-eval.md` draft, `references/quality-bar.md`), `agents/` (deterministic tools: quote, equity, trader), `tools/` (Morningstar PDF parsing, report organizing), `providers/` (`QuoteProvider`/`FundamentalsProvider` interfaces — Finnhub covers quote/fundamentals, Twelve Data fills in historical closes for RSI/MA since Finnhub's free tier blocks that endpoint, `HybridQuoteProvider` pairs the two, Morningstar implements `FundamentalsProvider`), `contextTools.ts`.
- `node/src/domains/calendar/` — read-only Google Calendar domain, stood up specifically to validate the harness generalizes: `skills/daily-agenda.md`, `googleAuth.ts`, `setup.ts` (OAuth bootstrap), `tools/calendarClient.ts`, `contextTools.ts`.
- `node/src/domains/travel/` — trip-cataloging domain: `skills/catalog-trip-year.md` (the fat skill — the full judgment process for turning a year of Gmail + the Maps Timeline export into per-trip markdown files), `tools/timelineClient.ts` (deterministic: parses `<SNESTACK_BRAIN_ROOT>/travel/Timeline.json`, excludes routine places visited on 8+ distinct days, clusters the rest into candidate away-from-home date ranges), `contextTools.ts`. There is **no Gmail context tool** — this harness has no Gmail access, so `run-skill travel catalog-trip-year <year>` can't run end-to-end like the other domains. The automated Gmail path (`snestack travel catalog <year>`, and the nightly `scripts/travel-catalog-backfill.sh` built on it) exists but is **deprecated and unscheduled** as of 2026-10-07 — one large API call per year costs more than it's worth. Use `snestack travel prep-catalog <year>` instead: it assembles the skill body + that year's timeline clusters into one prompt (`--out <file>` to save it) that you paste into a Claude session that does have Gmail + Google Maps access. Output convention (per-trip file shape, `00-index-<year>.md`) is documented in the skill file itself — keep it in sync as the process improves, and re-run past years as it does.
- `brain/`, `reports/` (Morningstar PDFs), `travel/` (per-year trip catalogs + `Timeline.json`), and `snestack.db` — all live outside the repo, under `<SNESTACK_BRAIN_ROOT>/` in a Google Drive-synced folder (default `~/Documents/personal-brain`, but set to wherever your Drive actually syncs — e.g. `~/Google Drive/My Drive/personal-brain`). One directory setting (`SNESTACK_BRAIN_ROOT` in `.env`) controls all of these; the db path is derived from it (under `financial/`), not configured separately. `brain/investing/public/companies/{TICKER}.md` holds the user's own stated thesis plus a dated history. See `.gitignore` and `node/README.md`'s Database section.

**Current path**: `snestack run-skill <domain> <skill> <subject>` — loads the skill's frontmatter, resolves `requires`/`references` via that domain's context tools, runs the assembled prompt through Claude. The old hardcoded-judgment path (`analyze`/`batch`/`retry` → `orchestrator.ts` → `CfoAgent`, plus the `scheduler` cron installer that ran `batch`) has been removed. Financial ingestion and judgment are fully separated: `snestack data-refresh --tier <intraday|daily|weekly>` is the only command that ever calls Finnhub/Twelve Data/Morningstar, on its own cadence, persisting what it fetches into `snestack.db`'s `fundamentals`/`quotes` tables; `run-skill`/`data-dump` only ever read that cache (falling back to a live fetch, logged as a warning, only if the cache is missing or badly stale). A skill's frontmatter can declare a `gate:` (RSI, price-move, age, input-changed triggers; `core/gate.ts`) so `run-skill --gated` skips the model call when nothing worth a fresh look has happened, and `verdict: true` makes it end with a `VERDICT: LABEL | confidence | reasoning` line that `build-signals` reads deterministically (no second model call). Four cron jobs make up the pipeline: `node/scripts/data-refresh-intraday.sh` (live price, every 30 min market hours), `node/scripts/data-refresh-daily.sh` (fundamentals + RSI/MA nightly, Morningstar re-parse Mondays), `node/scripts/daily-analysis.sh` (gated `long-term-quality` → `build-signals` → `notify`/`notify-summary`, nightly), and `node/scripts/swing-check.sh` (gated `swing-trading-large-cap` → `build-signals` → `notify`/`notify-summary`, several times a day market hours). Every automation run records `run.jsonl`/`run.json` (steps, per-call tokens, cost, gate decisions; `core/runLog.ts`), staged locally under `~/Library/Logs/snestack/runs/` and published to `<brain>/financial/signals/<date>/` (or `<brain>/financial/runs/<script>/<date>/...` for the three that fire multiple times a day) when the run finishes; `snestack run-check` summarizes recent runs and cache staleness for a person or watcher agent.
